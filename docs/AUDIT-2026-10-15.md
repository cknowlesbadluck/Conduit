## Key Features
- MCP tool surface (agents, tasks, grants, contacts, resources, integrations, bridge) with per-tool scope gating.
- Capability grants with subject binding and admin role; Postgres-backed store.
- Unauthenticated `/ready` and `/diagnostics` that don't echo stored secrets (#226). **Caveat:** `/diagnostics` returns `PUBLIC_URL`/`MCP_RESOURCE_URL` verbatim, so URL userinfo (`https://user:pass@…`) would leak. See weakness 8.
- Bounded surfaces: retention, redaction, timeouts, pagination.
- Portfolio probe: classifies each plane honestly (stranger/alias-absent/edge-503 are NOT ok) and, with #241, flags drift against pinned expectations (#241, merged 2026-10-16 14:08 EDT).

## Structural Weaknesses
1. Grant admins can act across subjects, and only the grant's creator (`createdBy`) can revoke it, not other admins. Fixed in #238, but not merged (runtime/auth: owner review).
2. Defense in depth: the expiry comparison fails open on an unparseable `expiresAt`. Supported paths (Zod datetime, `Date.parse` check, `timestamptz`) already prevent one, so this is reachable only with a corrupt internal object (#234 open; low priority).
3. Production lockdown keys on `NODE_ENV` alone (#206 → #212 stack; #212 conflicting).
4. At the SSE subscriber cap, the 200 headers are flushed before the throw, so the client gets a closed connection instead of a clean 503 + Retry-After (#217, conflicting).
5. Workers fetch handler returns fake ready/zero counts (#213).
6. Postgres TLS isn't verified by default (#155: needs owner Render env first; #162 overlaps).
7. Entropy: stacked PRs (#211/#212/#217 share a stale base), long-lived red drafts (#119, #120), and an owner-side Workers Builds check red on every PR.
8. `/diagnostics` `resource` echoes the configured URL verbatim, including any userinfo. Fix: reject userinfo in `loadAuthConfig` or redact it in `runDiagnostics` (runtime PR; owner review).

## Recommended New Implementations
1. **Drift-aware probe** (#241, merged this pass): pinned contractRevision + exact owner-gate set; `--drift-only` exit mode for the scheduled workflow.
2. Add a gating `--drift-only` step to `.github/workflows/portfolio-probe.yml`. It must not have `continue-on-error` or `|| true`, and the summary step should keep `if: always()`, so a scheduled run goes red only on real drift.
3. One grants hardening train: #238 → #234 → #206 → #212, rebased in that order, each with an authz-matrix test.
4. A PR-entropy budget: at most 8 open non-draft PRs; anything conflicting for more than 3 days gets closed with a replacement link.
5. Add a commit SHA to `/ready` so deploy parity is provable. Tag 0.9.0 only when every C10 exit criterion in `docs/PORTFOLIO-ROADMAP-10-PHASE.md` holds; publish the contractRevision change policy in SPEC.md.
