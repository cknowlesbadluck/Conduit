# Conduit 0.8 Production Coordination Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prove real MCP/OAuth interoperability, strengthen durable multi-agent coordination, and make production operation measurable without expanding Conduit's scope.

**Architecture:** Keep Render/Node/Express as the canonical runtime and PostgreSQL as the production coordination store. Add black-box HTTP/MCP coverage around the existing server boundary, preserve capability and actor policy as the security boundary, and expose only bounded coordination/diagnostic primitives.

**Tech Stack:** TypeScript, Node.js 20+, MCP TypeScript SDK v2, Express 5, PostgreSQL, GitHub Actions, Render, Descope OAuth 2.1.

**Spec:** `docs/superpowers/specs/2026-09-15-conduit-v0.8-production-coordination-design.md`

## Global Constraints

- Conduit remains project-agnostic and separate from Resonance.
- Render is the canonical Node deployment.
- PostgreSQL is authoritative for production persistence.
- Production external calls remain deny-by-default through capability grants.
- Raw paths determine authorization; sanitization is logging-only.
- No credentials, access tokens, provider secrets, or database URLs may appear in diagnostics or ordinary logs.
- Every production behavior change requires a failing regression test before implementation.
- CI must pass `npm ci`, `npm run typecheck`, `npm test`, and `npm run build`.
