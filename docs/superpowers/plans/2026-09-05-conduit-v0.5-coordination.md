# Conduit v0.5 Coordination Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add authenticated actor binding, first-class project/resource scoping, and comprehensive lifecycle/security coverage to Conduit without making it project-specific.

**Architecture:** Keep the existing store/MCP split. Extend the relational model additively with projects, resources, nullable project scope on existing records, and an agent identity binding. The MCP layer derives actor identity from authenticated OAuth claims and binds logical-agent parameters before calling the store; the store retains explicit parameters for deterministic unit tests and development mode.

**Tech Stack:** Node.js 20+, TypeScript, MCP TypeScript SDK v2, Express 5, Zod 4, PostgreSQL/pg, Node test runner, existing Descope OAuth configuration.

**Spec:** `docs/superpowers/specs/2026-09-05-conduit-v0.5-coordination-design.md`

## Global Constraints

- Conduit is a **project-agnostic development coordination layer**.
- Do not hard-code Resonance or any other application into Conduit.
- Prefer free or already-connected development resources.
- Do not require a Mac or local developer machine for coordination workflows.
- Conduit coordinates work and resources; it does not become part of the application being developed.
- Do not store credentials or secrets in resource metadata.
- Do not invent a new privileged OAuth scope; use only the existing configured read/write scopes unless a future authorization change is explicitly designed.
- Preserve backward-compatible unscoped task workflows.
