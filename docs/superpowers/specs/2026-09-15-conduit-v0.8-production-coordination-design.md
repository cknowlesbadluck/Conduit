# Conduit 0.8 Production Coordination Design

## Goal

Advance Conduit from a hardened MCP bridge into a reliable production coordination layer for independent AI agents, tools, MCP servers, and development resources, while keeping its scope deliberately smaller than Resonance.

## Scope

Conduit 0.8 has four independently testable workstreams:

1. **MCP/OAuth interoperability** — prove the real HTTP request path and make diagnostics useful enough to identify client compatibility failures.
2. **Durable coordination** — make PostgreSQL the authoritative production coordination store, with concurrency-safe task lifecycle behavior and bounded reads.
3. **Agent collaboration** — strengthen task claiming, handoff, project context, event replay, and identity binding as stable cross-agent primitives.
4. **Operational readiness** — improve deployment verification, release checks, observability, and runtime diagnostics without introducing a second application architecture.

## Non-goals

- Conduit will not become Resonance.
- Conduit will not embed project-specific application logic.
- No provider-specific UI is required for the core server.
- No paid infrastructure is required for the baseline deployment.
- Cloudflare Workers is not a production dependency unless its runtime path is independently proven; Render remains the canonical Node deployment.

## Architecture

The canonical production path is:

`MCP client -> OAuth authorization server -> Conduit /mcp -> authenticated actor -> capability/identity policy -> coordination or integration tool -> PostgreSQL`.

Render remains the canonical runtime for the current Node/Express implementation. PostgreSQL is the durable store whenever production is configured with `DATABASE_URL`. Development may continue using the in-memory store.

The public contract remains the MCP endpoint `/mcp`, with `/health`, `/ready`, protected-resource OAuth metadata, and authenticated `/events` as supporting surfaces.

## Interoperability contract

A compliant client must be able to:

1. Request `/mcp` without a token and receive a standards-compatible bearer challenge.
2. Discover protected-resource metadata.
3. Discover the configured authorization server.
4. Complete authorization-code + PKCE using the authorization server's advertised mechanism.
5. Present the resulting bearer token to `/mcp`.
6. Initialize an MCP session.
7. Discover tools.
8. Execute a safe read-only coordination tool.

The test suite must exercise the HTTP/MCP transport rather than only calling internal functions.

## Security contract

- Production OAuth discovery, issuer, authorization, token, and JWKS URLs must be HTTPS.
- Raw request paths are authoritative for authorization; sanitized values are logging-only representations.
- Capability grants remain deny-by-default for external calls.
- Actor binding remains the identity boundary for coordination mutations.
- SSRF protections remain authoritative for MCP bridge calls.
- Secrets, access tokens, provider credentials, and database URLs must never enter diagnostic output or ordinary logs.
- Pagination must be bounded at the database query layer.

## Coordination contract

Tasks support atomic claim, ownership-safe completion, release, and handoff. PostgreSQL concurrency behavior is authoritative in production. Cursor-based list operations use deterministic `(created_at DESC, id DESC)` ordering and must not duplicate or skip records solely because new rows are inserted while a client paginates.

Project-scoped context is independently bounded per collection. Event replay is bounded and project-filterable. Agent identity is actor-bound and cannot be impersonated by ordinary writes.

## Operational contract

Every release must provide:

- passing typecheck, tests, and build;
- a successful Render deployment from the release commit;
- `/health` success;
- `/ready` reporting the release version and persistence mode;
- OAuth metadata parity checks;
- an authenticated MCP smoke path;
- coordination lifecycle coverage;
- no unresolved high-severity security review findings.

## Success criteria

Conduit 0.8 is ready when a fresh MCP client can authenticate and use a safe coordination tool against the deployed Render service, two independent authenticated actors can safely coordinate a task through PostgreSQL, and the repository has automated regression coverage for the entire request path.
